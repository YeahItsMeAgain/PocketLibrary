# Spine generation runs on-device on a required ONNX model bundle

Spine art is produced inside the app by a Rust pipeline on ONNX Runtime: DBNet text detection, a CIELAB text mask, then either a text-free crop or a MI-GAN inpaint, gated by a 52 × 236 residual-text check. We considered a hosted inference service and rejected it. A hosted route adds an API key to a local-first reader, uploads every cover, makes output non-reproducible, and stops working offline. The prototype suite already proves the local route end to end on an arm64 phone, so the question was delivery, not feasibility.

The models are a **required runtime dependency**, not a bonus. Bundle `spine-v1` is 41,229,063 B: det FP32 (2,432,880 B), rec FP32 (10,690,752 B), keys (26,250 B) and MI-GAN (28,079,181 B). The detector stays FP32 because that is the version the validated pipeline used; INT8 detection was slower and weaker on display type. The intended production delivery downloads it automatically on first run, resumable, SHA-256 verified against hashes compiled into the app, installed atomically and cached; the download is always visible and cancellable. Build 0.1.8 still bundles the same files as assets and extracts them on first use, so the pipeline and cache layout are identical either way; the downloader ships in a later ticket. Without the bundle the shelf still paints typographic cloth spines; it just offers no art spines.

MI-GAN is required because the inpaint route is what keeps text-heavy covers passing after download. LaMa is excluded in every form: FP32 is 208 MB with roughly 1 GB peak memory, and the INT8 Conv-only build leaves visible chroma scars at 18–20 s per book. rec INT8 is excluded too, because it returned no text on every text spine tested, which would silently disable the QA gate. Wrap is the default presentation because it is the only style that reads at 33 px on a shelf and gives the spine and back somewhere to live. Only **Wrap, Full-bleed and Cloth** ship: Full-bleed is the alternate, Cloth is the automatic fallback for review and fallback verdicts, and Hybrid, Textless and Editorial are deleted rather than hidden. The style set shrank because six renderers multiplied maintenance and RTL/contrast fixes for styles nobody chose; Full-bleed carries the text-forward case with title and author centred as one block over a gradient scrim (two lines max, shrink to fit, never truncate), and Wrap rail type uses the same contrast guard.

**Generation is automatic.** A spine job is queued for every path that yields a cover and a page count — download, import, scan, manual edit, metadata enrichment, manual cover pick — rather than waiting for the user to open a studio. The book appears immediately in Cloth and swaps when the art is ready. A single FIFO worker runs automatic jobs one at a time; manual Generate jumps the queue; the queue persists across process death and waits for models instead of dropping jobs. Progress is one quiet global chip (“Preparing spines · n of m”) plus per-book state, with real stage labels (preparing art, removing text, checking) and no fake percentage; it is hidden in the reader and one “Stop preparing” control pauses automatic work. Automatic jobs also pause while the reader is open. A failed job retries once, then leaves Cloth with a persistent marker and a detail note. The existing library is backfilled once at low priority. The cache is capped at 200 MB LRU and stores only runtime files (`art.jpg`, `spine-2x.jpg`, `fallback-spine.jpg`, `run.json`, `qa.json`, `artifact.json`); `source.jpg` and `mask.png` are scratch.

**Style is per book.** `books.spine_style` (migration 6, default `wrap`) records the chosen presentation so it survives restart and sync of the book row. A style switch re-renders from cached art and never invalidates the cache key or re-runs the pipeline. Changing a cover cancels and replaces that book's job. RTL titles (Hebrew first) are handled now with direction detection, mirrored alignment and a fixture. Unknown page counts generate from a clamped ~320-page estimate labelled `approximate`. Build 0.1.8 (versionCode 1008) still bundles the models; the first-run downloader is split into a separate release ticket.

Consequences: the App Store/Play listing and first run carry a ~41.2 MB model download once the downloader ships, which needs a storage guard and honest progress UI; there is no keyless public spine API to lean on, so quality improvements mean shipping new weights; the automatic queue adds a migration and persisted job state that must be crash-safe; and phone performance is still unmeasured — host reference is 2.6–13.8 s and 450–500 MB peak, so the UI is designed for 5–20 s and every device claim waits on the Android device pass. A curated pack remains an optional bonus, remote generative art stays out of scope, and `bookcover-js` remains a design reference only.
