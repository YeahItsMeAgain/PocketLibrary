# Spine generation runs on-device on a required ONNX model bundle

Spine art is produced inside the app by a Rust pipeline on ONNX Runtime: DBNet text detection, a CIELAB text mask, then either a text-free crop or a MI-GAN inpaint, gated by a 52 × 236 residual-text check. We considered a hosted inference service and rejected it. A hosted route adds an API key to a local-first reader, uploads every cover, makes output non-reproducible, and stops working offline. The prototype suite already proves the local route end to end on an arm64 phone, so the question was delivery, not feasibility.

The models are a **required runtime dependency**, not a bonus. Bundle `spine-v1` is 39,588,893 B: det INT8 (792,710 B), rec FP32 (10,690,752 B), keys (26,250 B) and MI-GAN (28,079,181 B). Production downloads it automatically on first run, resumable, SHA-256 verified against hashes compiled into the app, installed atomically and cached; the download is always visible and cancellable. The test APK bundles the same files as assets and extracts them on first use, so the pipeline and cache layout are identical either way. Without the bundle the shelf still paints typographic cloth spines; it just offers no art spines.

MI-GAN is required because the inpaint route is what keeps text-heavy covers passing after download. LaMa is excluded in every form: FP32 is 208 MB with roughly 1 GB peak memory, and the INT8 Conv-only build leaves visible chroma scars at 18–20 s per book. rec INT8 is excluded too, because it returned no text on every text spine tested, which would silently disable the QA gate. Wrap is the default presentation because it is the only style that reads at 33 px on a shelf and gives the spine and back somewhere to live; Hybrid is the alternate, and Cloth is the automatic fallback for review and fallback verdicts.

Consequences: the App Store/Play listing and first run carry a ~39.6 MB model download, which needs a storage guard and honest progress UI; there is no keyless public spine API to lean on, so quality improvements mean shipping new weights; and phone performance is still unmeasured — host reference is 2.6–13.8 s and 450–500 MB peak, so the UI is designed for 5–20 s and every device claim waits on the Android device pass. A curated pack remains an optional bonus, remote generative art stays out of scope, and `bookcover-js` remains a design reference only.
