# 24: Send diagnostics should open the share sheet

> *This was generated by AI during triage.*

**What to fix:** “Send diagnostics” writes a file through the save picker. It should hand the zip to the Android share sheet, with the save picker only as a fallback.

**Category:** bug
**Status:** resolved

## Evidence

- The WebView path prefers `navigator.share({ files })`, but Tauri's Android WebView does not offer file sharing, so it always falls through to `save_diagnostics`.
- Diagnostics show `prepared … bytes for sharing` followed by save-picker activity.

## Agent Brief

**Current behavior:** The app builds the zip in Rust, returns the bytes to the WebView, and the WebView attempts a web share that is unavailable on Android before opening the save picker.

**Desired behavior:** On Android, the shell stages the zip as a readable in-memory content URI and opens a native `ACTION_SEND` chooser directly. The user sees the usual share targets (mail, chat, drive, etc.). Cancelling or an unavailable chooser should fall back to the existing save flow rather than losing diagnostics. Desktop keeps the current save fallback.

**Acceptance criteria:**
- [ ] Tapping Send diagnostics on Android opens the system share chooser with `pocketlibrary-diagnostics.zip`.
- [ ] The shared file has MIME type `application/zip` and readable content.
- [ ] If native sharing fails, the save picker still works.
- [ ] The result line says diagnostics were handed to the share sheet.
- [ ] Frontend tests cover the native-share path and the fallback.

**Out of scope:**
- Uploading diagnostics to a server.
- Changing the contents of the diagnostics zip.

## Resolution

Android now stages the zip as a readable in-memory content URI and opens the native `ACTION_SEND` chooser; unsupported/failed sharing falls back to the save picker. Diagnostics and adapter Playwright tests pass, and the Android target compiles.
