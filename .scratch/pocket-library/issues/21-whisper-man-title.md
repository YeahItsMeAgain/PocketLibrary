# 21: The Whisper Man title is truncated to “MAN”

> *This was generated by AI during triage.*

**What to fix:** The downloaded book “The Whisper Man” appears as “MAN”. The file is named from the Libgen row (`… The Whisper Man ebook …`), but the shelf shows only the last word.

**Category:** bug
**Status:** resolved

## Evidence

- `metadata::extract` always prefers the embedded EPUB title, even when it is a short suffix of the filename title.
- Libgen row titles often carry an “ebook” suffix, which is not stripped by `parse_filename`.
- Existing books are not re-extracted on rescan, so this book stays wrong after an app update unless the repair path updates it.

## Agent Brief

**Current behavior:** If an EPUB's embedded title is a short fragment such as `MAN` while its filename contains the full title, the fragment wins and the shelf shows `MAN`.

**Desired behavior:** A filename title that clearly extends a suspiciously short embedded title should win. Trailing acquisition words such as `ebook` should be removed. A rescan should repair an already-indexed book with this exact symptom, without overwriting normal embedded titles.

**Acceptance criteria:**
- [ ] An EPUB whose embedded title is `MAN` and whose filename is `Alex North - The Whisper Man ebook (2019).epub` is indexed as `The Whisper Man`.
- [ ] Normal embedded titles remain authoritative.
- [ ] Rescanning a library that already contains the wrong title repairs it.
- [ ] Core tests cover extraction and the scan-repair path.

**Out of scope:**
- General metadata editing UI.
- Online metadata enrichment.

## Resolution

Filename titles now strip trailing `ebook`/`e-book`, and a short embedded suffix loses to the full filename title. Rescan repairs an existing `MAN` row. Metadata, scan and full core suites pass.
