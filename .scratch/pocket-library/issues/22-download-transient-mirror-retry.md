# 22: Download fails immediately on a transient mirror error

> *This was generated by AI during triage.*

**What to fix:** Some books fail with “Trying another mirror failed. Try again in a moment.” even though a manual retry succeeds seconds later. The queue treats a transient 5xx from every mirror in one pass as terminal.

**Category:** bug
**Status:** resolved

## Evidence

Diagnostics show `ads page answered 500 Internal Server Error` for downloads 3, 6 and 7; retrying the same row moments later completes.

## Agent Brief

**Current behavior:** The downloader walks the mirror list once, with a fresh key retry only for expired keys. Any 5xx or other transient mirror failure moves to the next host; after one pass it fails the row.

**Desired behavior:** Transient mirror failures are retried with a short bounded backoff across another pass or two of the mirror list. A genuinely unavailable file still fails with the same user-facing error, and cancellation/offline remain responsive. Progress and mirror labels continue to update during retries.

**Acceptance criteria:**
- [ ] A fake mirror that returns 500 once and then serves the file completes without user retry.
- [ ] Exhausting every mirror on every pass still fails with `mirror_failed`.
- [ ] Cancelling during backoff stops promptly.
- [ ] Existing failover, resume and expired-key tests remain green.

**Out of scope:**
- Changing the Libgen search parser or mirror discovery.
- Unlimited retries or background auto-resume after the app closes.

## Resolution

The queue now makes up to three bounded passes over the mirror list for transient mirror failures, with cancellation-aware 200/500 ms backoffs. All 23 download tests pass.
