The spine engine,
on the phone.

A real PocketLibrary build with the on-device spine engine, which prepares spines automatically: after downloads, scans, the first-library backfill and cover changes. It finds the cover text, removes it, and renders Wrap, Full-bleed and Cloth without a network call, API key, or upload. The four ONNX models and ONNX Runtime are bundled for this test. This release makes cached spines hydrate the wall, generates missing spines on launch, paints cached art above the face, moves spine controls entirely into Edit, and makes opening a book faster.

Install

Sideload it over 0.1.9, or do a clean install if your phone has a debug or differently signed PocketLibrary.

  1. Download the APK on the phone (or copy it over).
  2. Open the file. If Android blocks it, allow Install unknown apps for the browser or file manager you used.
  3. If 0.1.9 is installed from this page: install straight over it. The release key is the same, the library is kept, and the database stays at schema 6.
  4. A debug build or a build signed with another key must be uninstalled first; Android will refuse the update otherwise.
  5. Open PocketLibrary. Spines start preparing automatically; on an existing library the backfill runs once at low priority, so the wall stays usable.

What changed in 0.1.10

The shelf hydrates itself

  • On launch, every cached spine is projected onto the wall without queueing a job, running inference or hashing covers.
  • A warm shelf paints its ready spines immediately; only new or changed covers enter the automatic queue.
  • A cached book whose strip is missing is generated automatically in Wrap, so the shelf heals instead of showing a bare face.

Cached art stays above the face

  • When a generated strip exists, it now paints above the cover face instead of being hidden behind it.
  • Cloth still keeps the face; Wrap and Full-bleed show the generated art, including after a relaunch.
  • The queue, progress chip, reader pause, failure marker and 200 MB cache from 0.1.9 are unchanged.

Read view and Edit layer

  • The book sheet is a read view: title, author, blurb, labels and status, with no Spine section and no editable controls.
  • Spine controls now live only in Edit, in the six sections: Details, Cover, Spine, Status & labels, Online details, Danger.
  • Edit opens at the top so the first section is in view, and Escape closes only the Edit layer.

Faster opening

  • The detail panel is preloaded and the open animation no longer scales, so a book opens without the previous delay.
  • Opening a book no longer resolves the engine or runs a status check; it only reads the artifact cache.
  • Cover art is painted directly rather than waiting on a second layout pass.

What to test

Upgrade and the warm shelf

  • Install over 0.1.9 without uninstalling. Your shelf, reading state, labels and per-book spine styles should be intact.
  • Relaunch on a prepared library: cached spines should appear on the wall without the queue starting, drawn above the face.
  • If one cached book has no strip, it should be generated automatically in Wrap and appear on the wall.
  • Open a book while it is preparing: the queue should pause, then resume when you go back.

Read, edit and open speed

  • Open a book: the read view should show no Spine section and no editable fields; tap Edit to reach the six sections.
  • Edit should open at the top, with Details in view rather than the bottom of the sheet.
  • Generate a spine in Edit and go back: the wall should show the new art above the face, with no read-view spine controls.
  • Open several books in a row: the panel should appear immediately, without the old scale animation or engine status call.

Known limits

This is a test build

  • Models are still bundled in this APK for testing. The production model downloader/cache is not part of 0.1.10.
  • arm64 only. It will not install on 32-bit, x86, or an emulator without arm64 translation.
  • ~64.4 MiB download plus ~41 MiB extracted models on first run. Leave roughly 120 MiB free.
  • Generation runs fully on the device. On a phone it is slower than the host timings in the evidence; the inpaint route can take noticeably longer than the crop route.
  • Release-signed, so it will not install over a debug build. Uninstall the old app first.
