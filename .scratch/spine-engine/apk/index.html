The spine engine,
on the phone.

A real PocketLibrary build with the on-device spine engine, which prepares spines automatically: after downloads, scans, the first-library backfill and cover changes. It finds the cover text, removes it, and renders Wrap, Full-bleed and Cloth without a network call, API key, or upload. The four ONNX models and ONNX Runtime are bundled for this test. This release fixes the reason art spines could stay invisible: the queue called a book done when an artifact file existed, while the wall only paints a decodable strip that passed the quality gate. A fallback or an unreadable artifact therefore finished forever — queue empty, no error, cloth shelf. Settings now shows Artifact, Shelf strip and Verdict separately, and Edit no longer jumps when you switch styles.

Install

Sideload it over 0.1.12, or do a clean install if your phone has a debug or differently signed PocketLibrary.

  1. Download the APK on the phone (or copy it over).
  2. Open the file. If Android blocks it, allow Install unknown apps for the browser or file manager you used.
  3. If 0.1.12 is installed from this page: install straight over it. The release key is the same, the library is kept, and the database stays at schema 6.
  4. A debug build or a build signed with another key must be uninstalled first; Android will refuse the update otherwise.
  5. Open PocketLibrary. Spines start preparing automatically; on an existing library the backfill runs once at low priority, so the wall stays usable.

What changed in 0.1.13

“Queue empty but cloth shelf” is fixed

  • 0.1.12 counted a book as done when artifact.json existed, while the wall only paints a decodable strip with verdict pass or review. A fallback, or an artifact that could not project, was therefore finished forever: the queue was empty, nothing failed, and the shelf stayed cloth.
  • Now there is one definition of done: a shelf-eligible projected strip. Anything else is regenerated on launch.
  • A fallback is retried automatically up to three attempts, then stays visible as needs attention in the chip, the shelf marker and Settings.

Settings tells you which layer failed

  • Artifact, Shelf strip and Verdict are separate columns, with a summary of how many books can actually paint art.
  • Retry all re-queues books without a shelf strip; Refresh re-reads the report.
  • Engine failures now carry the real on-device error into the attention row and spine.log, instead of “try again”.

Settings is centred, and Edit no longer jumps

  • The settings card was sized by the widest table cell, so it sat right of centre at 390 and was clipped at 320. It now fits the viewport, long paths wrap, and the table stacks below 520 px. Verified at 320 / 390 / 412.
  • Choosing Wrap / Full-bleed / Cloth re-ran the studio load and changed the stage height by 70–112 px. The stage is now stable across all three styles, with no scroll movement.
  • A fallback no longer persists Cloth onto the book, which used to hide later successful art permanently.

What to test

The shelf and the payload

  • Install over 0.1.10 without uninstalling. Your shelf, reading state, labels and per-book spine styles should be intact.
  • Relaunch on a prepared library: cached spines should appear on the wall immediately, in the first paint, without waiting for a hydration event.
  • Full-bleed spines should show the 20 px smoked rail with the long title running down it; Wrap spines should show the long title in the full run above the author.
  • Check a long title at 320 px: it should wrap to at most two lines and never overflow the spine.

If spines still don't appear

  • Open Settings → Diagnostics and export the diagnostics.
  • In spine.log, check for shelf: books N, strips M and hydrate: scanned … projected ….
  • If strips and projected are 0, the cache was not found: check the logged root and whether it says (present) or (missing).
  • If strips is greater than 0 but the wall is bare, the payload reached the shell but the strip did not paint — include that line in the report.

Known limits

This is a test build

  • Models are still bundled in this APK for testing. The production model downloader/cache is not part of 0.1.13.
  • arm64 only. It will not install on 32-bit, x86, or an emulator without arm64 translation.
  • ~64.96 MiB download plus ~41 MiB extracted models on first run. Leave roughly 120 MiB free.
  • Generation runs fully on the device. On a phone it is slower than the host timings in the evidence; the inpaint route can take noticeably longer than the crop route.
  • Release-signed, so it will not install over a debug build. Uninstall the old app first.
