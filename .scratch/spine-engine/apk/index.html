The spine engine,
on the phone.

A real PocketLibrary build with the on-device spine engine, which prepares spines automatically: after downloads, scans, the first-library backfill and cover changes. It finds the cover text, removes it, and renders Wrap, Full-bleed and Cloth without a network call, API key, or upload. The four ONNX models and ONNX Runtime are bundled for this test. This release also separates the book into a read view and an Edit layer, and gives Wrap and Full-bleed real-book vertical typography.

Install

Sideload it over 0.1.8, or do a clean install if your phone has a debug or differently signed PocketLibrary.

  1. Download the APK on the phone (or copy it over).
  2. Open the file. If Android blocks it, allow Install unknown apps for the browser or file manager you used.
  3. If 0.1.8 is installed from this page: install straight over it. The release key is the same, the library is kept, and the database stays at schema 6.
  4. A debug build or a build signed with another key must be uninstalled first; Android will refuse the update otherwise.
  5. Open PocketLibrary. Spines start preparing automatically; on an existing library the backfill runs once at low priority, so the wall stays usable.

What changed in 0.1.9

Read view and Edit layer

  • The book sheet is now a read view: title, author, blurb, labels, status and the spine are shown without editable controls.
  • Edit opens a separate layer with six sections in order — Details, Cover, Spine, Status & labels, Online details, Danger.
  • Editing no longer risks a stray tap in the read view; Escape closes only the Edit layer and returns to the book.

Autosave, Saved and Undo

  • Title, authors, pages and blurb save on blur; the blurb also saves after a short debounce while you keep typing.
  • Each field shows a Saved tick once the write lands, and closing Edit shows the new values immediately in the read view.
  • Cover and spine-style changes show an Undo toast that restores the previous cover or style.

Real-book vertical typography

  • Wrap and Full-bleed now share the type bands of a real spine: title in the upper third, author in the lower third, publisher mark at the base.
  • The middle third stays with the cover art, so a shelf reads as books rather than posters.
  • The same layout follows RTL titles, and switching Wrap to Full-bleed moves the background only, not the type.

Cached spines hydrate the shelf

  • On launch, every cached spine is projected onto the wall without queueing a job, running inference or hashing covers.
  • A warm shelf paints its ready spines immediately; only new or changed covers enter the automatic queue.
  • The queue, progress chip, reader pause, failure marker and 200 MB cache from 0.1.8 are unchanged.

What to test

Upgrade and the warm shelf

  • Install over 0.1.8 without uninstalling. Your shelf, reading state, labels and per-book spine styles should be intact.
  • Relaunch on a prepared library: cached spines should appear on the wall without the queue starting.
  • Leave the app on the wall during a backfill: the chip should show progress without blocking scrolling.
  • Open a book while it is preparing: the queue should pause, then resume when you go back.

Read, edit and undo

  • Open a book: the read view should have no editable fields; tap Edit to reach the six sections.
  • Change the title, authors, pages and blurb; each should show Saved, and closing Edit should show the new values.
  • Change the cover and the spine style, then press Undo on each toast and confirm the previous value returns.
  • Check Wrap and Full-bleed on a real cover: title upper third, author lower third, publisher mark at the base, art in the middle.

Known limits

This is a test build

  • Models are still bundled in this APK for testing. The production model downloader/cache is not part of 0.1.9.
  • arm64 only. It will not install on 32-bit, x86, or an emulator without arm64 translation.
  • ~64.5 MiB download plus ~41 MiB extracted models on first run. Leave roughly 120 MiB free.
  • Generation runs fully on the device. On a phone it is slower than the host timings in the evidence; the inpaint route can take noticeably longer than the crop route.
  • Release-signed, so it will not install over a debug build. Uninstall the old app first.
